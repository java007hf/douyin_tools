# 豆包上传桥接验证插件

这是独立的豆包上传插件，不更改抖音插件。工程生图表单通过同一桥接传入参考图。
它不自行计算签名、不读取页面私有变量。申请和提交仍由豆包原有上传客户端执行，
仅拦截当前页新发起的存储上传 POST，将图片字节和本次上传头交给本地 Python。
支持 fetch 和 XHR 两种传输；当前精确允许 HAR 已出现的两个存储域名。
0.1.5 额外登记本次 ApplyImageUpload 实际返回的 tos-*.snssdk.com 节点，
并记录每次上传的域名、传输方式及是否转交 Python；未登记节点不会被 Python 接受。
只有预期数量的 Python 传输及去重后的 commit URI 都齐全，报告才标记 done。
0.1.6 修复 XHR 完成回调竞态：在 ready-state 捕获阶段登记实际节点，
上传必须等待 Python 确认登记完成。0.1.5 实测第一张新节点上传先于 load 观察发生，
因此报告为 transport_bypassed；它不是“两张都经过 Python”的成功记录。
0.1.6 实测仍出现 SDK 上传先于观察回调启动，不能视为修复验收成功。
0.1.7 在存储 POST 入口暂停未知节点，最多等 15 秒取得申请响应并完成本地登记；
超时明确失败，禁止回退到浏览器原生上传。回归测试覆盖 SDK 回调早于全部观察回调的顺序。

1. 在项目目录执行：

   ```powershell
   python -B -m services.video_creator.tools.ai.doubao_upload_bridge --timeout 180 --image cache/doubao_baseline/upload-probe.png
   ```

2. 在 Chrome 扩展管理中开启开发者模式，加载此目录为已解压扩展。
3. 刷新已登录的豆包网页。0.1.3 默认自动连接，无需点启动。
4. 插件会取出 Python 指定的图片，放入豆包页现有的图片选择组件。无需手选图片或发送生成请求。
   若页面没有可唯一识别的图片选择组件，验证会报告错误，不猜测点击目标。
5. Python 应依次记录 apply、python_upload、commit，并输出 `state: done`。
   上传服务器需要返回正常成功响应，网页随后提交成功并获得图片 URI，才算通过。
6. 弹窗提供暂停/恢复连接。页面自动发送心跳，唤醒休眠的后台进程；刷新后自动恢复。
   只有收到本地图片任务时才接管上传，不会主动提交图片或视频生成请求。

桥接只监听 `127.0.0.1:18767`，180 秒后自动退出。上传 POST 不自动重试。
临时签名、令牌、图片字节不写日志；验证报告保存在持久 store 的
`video_creator/doubao_web/upload_verification/<验证ID>/verification.json`。
修改插件代码后需在 Chrome 中重新加载扩展并刷新豆包页。

0.1.7 已完成两参考图的浏览器申请/提交、Python 上传和独立 i2i 实测。
工程集成版 0.1.10 自动复用/打开图像创作页，并在派发前主动注入脚本，
等待页面上传组件就绪，避免升级后旧标签内容脚本失联。未接入参考视频上传。

上传节点按本次 ApplyImageUpload 返回值登记；已实测 `tos-lq-x.bytedancevod.com`。
未知节点先暂停，只有受支持域名且完成 Python 登记才放行；禁止原生传输绕过。
重用标签时会停用旧版页面钩子并注入新版，避免重复拦截。
