# 理解历史 → 分平台内容

抖音和 YouTube 理解历史的“发布”按钮打开同一个平台多选对话框。可以选择小红书、微信公众号、抖音图文，另行选择“生成后自动发布”。小红书通过本地 Chrome 创作中心发布；抖音也已接入独立网页适配器，公众号仍待接入。自动发布只作用于本次新生成的小红书及抖音内容，绝不补发历史任务。

## 当前内容能力

- 使用 Admin 的“视频理解 LLM”配置及共享跨进程 FIFO 模型准入；不使用 AI 视频 Agent 或直接生图表单的提示词助手凭据。
- `styles/*.md` 是随项目版本管理的编辑规则，分别约束标题、正文、卡片数量、文风和配乐建议。每个生成版本记录规则哈希。修改规则只影响新的内容版本。
- 输入仅为已完成的标题、摘要、观点、时间线、理解范围和来源链接，不向模型传入提及评论、回复正文或其他平台的生成稿。
- 模型输出必须通过结构、字数、卡片数量与配乐建议校验；失败时最多修正一次。各平台独立失败，不丢弃其他平台已生成的内容。
- 理解成稿和发布改写共享直接讲述规则；标题、导读、正文、封面、卡片及理解章节检测“视频还对比了”“作者对……”等典型旁观转述。补卡、扩写和压缩使用同一规则；一次模型修复后仍不合格则停止，不进入出图。旧草稿在发送前也检查；不会机械替换人称或冒领他人经历。检测属于明确句式门禁，不等同于完整语义审核。
- 每页 `image_prompt` 交给真实生图工具，优先使用后台已启用的 Doubao Mock Provider；明确返回当天生图额度用尽后，自动切换本地 Flux / Qwen Image。Pillow 负责最终文字排版，原始 AI 配图单独保存和下载。图片明确标为 AI 配图，不冒充新闻照片或真实行情。
- 日额度状态保存在 `store/video_creator/image_route_state.sqlite3`，按 Provider/登录配置标识和 Asia/Shanghai 自然日共享，服务重启保留，次日重新优先尝试 Doubao。不预设每天额度数量。登录失效、频率限制、网络超时和结果不明不视为日额度用尽，不盲目切换或重复提交。
- 本地模型默认优先选择已安装的 Flux，其次 Qwen；`PUBLICATION_LOCAL_IMAGE_MODEL` 可明确指定上述受支持模型，`COMFYUI_URL` 指定本地服务。原图按 1344×768 生成，并保留模型、seed、工作流、ComfyUI prompt_id、心跳、错误和切换原因。ComfyUI 必须已启动。
- 本地生图使用共享理解准入，在持有准入时卸载 Ollama 理解模型；生图结束后释放闲置 ComfyUI 模型再交还准入。此保护不等同于整个项目尚待建设的跨所有生成任务 GPU 资源调度。
- 文案阶段保存配乐情绪、搜索词和理由；抖音发布阶段搜索真实曲库并绑定音乐，小红书目前只保存建议。公众号文章不依赖背景音乐。
- 同一条历史的详情和发布弹窗可查看所有生成版本、正文、图片和配乐建议，下载 Markdown、JSON 和包含 PNG 的 ZIP 素材包。
- 已生成或生成失败的平台提供“重新生成内容”和“重新生成并发布”入口：从原理解记录使用当前 LLM/提示词生成独立新版本，前者仅存草稿，后者通过文案、配图与发布校验后发送；保留原稿和其他平台回执。口吻失败的旧稿禁用直接发送；结果不明时先核对，不通过重新生成绕过。界面持续刷新生成与发送状态，网络重试复用请求标识。

## 状态和存储

`publication_batches`、`publication_targets` 与所属 `understanding_history` 同库，但独立存储，后续 @回复和历史更新不会覆盖内容。生成状态：`pending` → `running` → `generated` / `error`；批次在所有平台结束后为 `done` 或 `error`。小红书发送状态独立记录为未发送、发送中、等待登录、失败、结果待核实或已发布；必须取得可验证笔记ID才标记已发布，提交结果不明禁止自动重发。

素材持久化于对应服务的 `web_downloads/publications/<history-id>/<batch-id>/<platform>/`。例如默认抖音目录是 `store/douyin/web_downloads/publications/`；YouTube 使用 `store/youtube/web_downloads/publications/`。数据库内只保存可移植的应用下载 URL，不保存凭据或任意外部路径。

同一历史按平台防重，不同平台可独立创建批次并进入共享模型FIFO；同平台生成、发送或发布结果待核实期间拒绝重复提交；HTTP `request_id` 防止同一次请求重发。重新生成保留旧版本。生成期间禁止删除历史。服务重启将未完成平台标记中断；不自动重发，也不伪装成完成。删除历史保留其媒体文件，遵循现有历史删除行为。

## HTTP

`POST /api/understanding-history/<history-id>/publications`

```json
{"platforms":["xiaohongshu","wechat","douyin"],"auto_publish":false,"request_id":"a-unique-request-id-1234"}
```

返回 `202` 及 `batch_id`。轮询原历史详情接口的 `publications` 字段至所有平台结束。历史列表包含各平台最新版本的精简状态。YouTube 同时支持 `/api/history/<history-id>/publications`。

## 封面与图库优先

每个平台独立生成 cover：3个标题候选、选中标题、短副标题、视觉风格、主视觉提示词及选择理由。第一张配图是封面；标题由 Pillow 排版，避免生图文字错误。小红书支持白底红字、相关成年人主视觉、自然场景；公众号支持杂志图文和场景；抖音支持高对比大字、人物和场景。封面另存 `cover.png` 并纳入素材包。

配图顺序为已启用的 Pixabay、Pexels 图库 → Doubao Mock → 当天额度用尽后的本地模型。到后台“图库配图”保存对应 API Key 后启用。未配置图库时明确记录 `not_configured`，不会假装已搜到照片。截至2026-11-04调研时，Pexels 官方提示暂停发放新 Key，已有 Key 用户可配置；申请开放情况以官网最新说明为准。Unsplash 因其展示、署名和下载回调等要求，当前未接入。

每张卡片由相同的理解 LLM 提供具体英文摄影搜索词；仅使用图库 photo 类别，并过滤明确 AI 标记和不可信下载域名。图库标签过滤不等同于视觉鉴伪，不能保证图库中没有误分类素材。按关键词相关性、分辨率与方向筛选，同一作品避免重复照片。搜索结果在 `store/video_creator/stock_search_cache.sqlite3` 缓存24小时；API Key 只存在 Provider 配置中，不进入缓存键原文、图片轨迹或前端明文。

原图、作者、源页面、许可名称与许可链接随任务保存；历史详情、Markdown 和 JSON 都保留来源，完整包内包含原图与封面。图库没有合适照片、接口失败或没有 Key 时会显示 AI 补图原因。小红书 AI 提示词改为暖色自然摄影，避免冷色商务插画、3D玻璃和悬浮图表；内页配色同步调整。

官方接口说明：[Pixabay](https://pixabay.com/api/docs/)、[Pexels](https://www.pexels.com/api/documentation/)。图库使用仍需遵守具体素材及平台许可，不将图库人物当作原作者或新闻当事人。

## 故障诊断与定向图库生成

历史行使用三列布局：完整标题、发布、删除；各平台状态标签独占下一行。图库工具可用 `stock_only=True, sources=("stock_pixabay",)` 对用户明确指定的单次任务禁用 AI 回退，失败会明确记录而不暗中调用豆包。自然语言摄影搜索词过于具体时，允许有限次缩短为具体场景词，不进行批量抓取。

豆包网页流完成但没有图片时，保留有限的事件类型、失败类型与脱敏回复文本；不保存原始 SSE、Cookie、请求签名或凭据。明确的日额度用尽文本交给既有配图工具识别；未知空结果不自动重新提交。历史仅记录事件数量的旧任务无法据此追认业务根因，需与后续完整诊断区分。

## 小红书大图排版

小红书内页使用独立 `xhs_layout.py`，支持大图在上和文字在上的两种内容驱动布局。照片铺满画布宽度；正文按真实文字量选择字号和图片高度，不保留固定底部缩略图空槽。非封面卡片至少90字，优先110–180字，并要求解释观点及其条件；仅依据已有理解内容扩写，不补造事实。白底红字封面的副标题紧随主标题，下方使用大幅照片；标题平衡断行，正文限制中文标点出现在行首。

发布内容预览在宽屏按标题封面、正文内容分为两栏，760px以下上下排列。封面、内页及原图均通过原生dialog弹窗预览同一版本的图片；支持左右按钮、键盘方向键和Esc关闭，关闭后恢复触发按钮焦点。来源和许可仍保留独立外链。

## 小红书发送

安装Chrome和项目Playwright依赖。通过 `POST /api/publications/xiaohongshu/login` 打开独立登录窗口，登录态存于 `store/douyin/xiaohongshu_publisher/browser/`，不复制其他浏览器凭据。`POST /api/understanding-history/<history-id>/publications/<batch-id>/send` 发送指定版本；`POST /api/publications/xiaohongshu/status` 用job_id查询。YouTube同样支持这些入口。发布严格使用生成卡片顺序，校验标题及正文，支持新版xhs-publish-btn和旧按钮；平台回执、预览和失败诊断保存在该持久目录的jobs/<job-id>/下，SQLite负责跨进程互斥。配乐尚未绑定。页面变化、登录过期或平台审核仍可能中断发送。

发送兼容新版自定义控件，并等待上传请求结束与短暂稳定窗口再提交。新增 `/verify` 只读核对笔记管理入口；无法取得唯一回执时保留待核实状态，不能当作失败自动重发。已用六张图文完成真实实发，发布成功页面与平台笔记ID均已核对。

## 持久化发布队列

抖音和 YouTube 工作台共用 `store/douyin/xiaohongshu_publisher/jobs.sqlite3` 的 FIFO 队列。发布、登录、预览和只读核对均按入队顺序使用同一个浏览器；页面显示排队位置，同一版本不能重复入队。浏览器锁在窗口关闭后才释放，避免上一条清理与下一条启动重叠。预览保留窗口和等待登录期间会占用队列。

未开始的排队任务在服务启动或后续入队时恢复；已经运行但进程退出的任务标为中断，提交阶段退出标为结果待核实，均不自动重新发布。单条任务失败后释放浏览器，后续任务继续。队列回归覆盖并发入队、跨进程FIFO、清理互斥、异常释放和恢复，不执行真实发布。

登录成功后保存独立浏览器登录态，保留窗口最多5分钟供检查；用户关闭窗口不视为失败。有后续任务入队时，登录窗口自动退出并释放浏览器锁，发布无需重复点登录。

## 独立部署与浏览器运行环境

抖音与小红书发布均由项目后端通过 Python 子进程、SQLite 队列和 Playwright 驱动 Chrome，
不调用 ChatGPT、Codex、Computer Use 或其浏览器工具，也不需要安装或运行 ChatGPT。
调用链为：网页发布按钮 → HTTP API → PublicationEngine → 持久化队列 worker → 平台适配器 → Chrome。

当前两个适配器均以 `channel="chrome", headless=False` 启动服务所在机器上的浏览器。
因此部署机器需安装项目 Python/Playwright 依赖和 Google Chrome，并提供可用的图形桌面会话。
首次登录和验证码在这台机器的浏览器完成；远程访问工作台不会把服务端 Chrome 窗口显示在访问者电脑上，
需要通过远程桌面等方式在部署机器完成登录。之后复用 `store/` 中的平台独立登录态。
仅有无桌面容器或普通无头 Linux 服务的部署，当前尚不支持直接使用这套有界面登录流程；
需要另行配置虚拟显示及可访问的登录界面，或实现远程浏览器执行端。

平台改写统一调用 Admin 的视频理解 LLM（`douyin_understanding`），抖音与小红书只切换平台风格文件、配图方案及排版。新版本内容记录 `editorial_trace`，保存模型名、配置类别、风格文件、来源历史和调用时间，页面展示模型名；不保存密钥。

抖音卡片正文目标50–70字符（含标点），上限80字符；超长时由同一视频理解LLM定向压缩指定页，保留标题、配图与其他页。模型返回缺页、重复索引或仍超长时拒绝结果，不直接截断。进度记录初稿、补齐、扩写/压缩及整体修复阶段。


真实网页兼容规则：抖音标题上限20字，历史长标题优先复用同一次LLM生成的短封面标题，不直接截断。
富文本校验仅忽略空白及编辑器插入的U+200B标记，保留实际文字与emoji连接符；
上传需同时满足网络完成与页面上传计数完成。金融类正文附固定的来源观点/原作者测算示例标注。
2026-11-05实发使用 `/web/api/media/aweme/create_v2/` 的HTTP 200、`status_code=0`及作品ID作为回执，
发布标题为“美国财富自由门槛”，5张1080×1440卡片均来自Pixabay。配乐未自动绑定。
运行中的旧服务需要空闲重启，才能加载新HTTP入口和生成修复；不可为加载代码中断正在执行的理解任务。


## 抖音强制配乐

`douyin_music.py` 使用本地视频理解LLM生成的最多三个搜索词，操作创作者中心“选择音乐”搜索，
只采用真实曲库返回的可选歌曲ID、曲名、作者和时长。支持当前 `tsearch.amemv.com` 搜索响应，
区分可选歌曲的 `mid` 与其子节点 `original_sound` 的不同ID，不伪造曲目或授权信息。
选曲后必须显示“修改音乐”和真实曲名；找不到可用音乐时停止，不能静默无配乐发布。

发布请求经 Playwright 路由校验 `item.common.music_id` 必须等于所选曲库ID，播放区间必须有效；
不匹配、未选择或零时长时，在请求发出前拦截。成功回执记录 `music_status=attached`、曲名/作者/ID和播放区间；
未取得平台回执的结果不能标为音乐已随作品发布。任务目录保存 `music.json` 与 `music-submission.json`。
